# Task Plan: task0001 — Reflowing section layout (FlowBox)

## Goal

The window's section list lays out horizontally with wrapping: sections
appear left→right in config order, sharing rows while width allows, and
wrap to the next row when it does not. All existing section behaviors
(reload, per-section update, styling, error rendering) keep working.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2

## Scope

### Files to Create
None.

### Files to Modify
- `internal/ui/sections.go` — swap the sections container from a vertical
  box to a horizontally-oriented flow container; adapt append/removal.
- `internal/ui/style.go` — replace the single inter-section gap constant
  with separate column/row gap constants; add the wrapper-node style reset
  to the generated stylesheet.
- `internal/ui/style_test.go` — cover the new stylesheet content.
- `design-system/tokens.yaml` — spacing description: セクション間 横 2 unit / 縦 0.
- `design-system/tokens.html` — same wording update as tokens.yaml.

## Design

**Container swap (`sectionsView`)**
- The container widget becomes GTK4's reflowing flow container with
  horizontal orientation. Configuration (all set at construction):
  - selection disabled (no selection/hover visuals) — FR4
  - non-homogeneous children (natural widths) — FR2
  - column spacing = 2 spacing units (12px), row spacing = 0 — FR3
  - minimum 1 child per line; maximum set high enough (e.g. 100) that it
    never constrains a row — FR2
- Section root widgets (label + output vertical box — internal structure
  unchanged) are appended in the order given to the set-sections
  operation; the container inserts its own per-child wrapper
  automatically — FR1.
- Removal during a rebuild passes the stored section root widget to the
  container's remove operation; the container resolves its wrapper from
  the child (postcondition: no wrapper widget remains parented after
  removal) — FR5.
- The window layer consumes the container as a generic widget; only the
  field's concrete type changes.

**Stylesheet (`style.go`)**
- The old single `sectionGap` constant is replaced by two constants:
  column gap (2 units) and row gap (0). Both are layout constants, not
  user-overridable style values, mirroring the token documents.
- The generated application stylesheet gains a reset for the container's
  auto-inserted child node: zero padding and zero margin — FR4.

**Token documents**
- Spacing descriptions in tokens.yaml / tokens.html change from
  "セクション間 0" to "セクション間 横 2 unit / 縦 0" — FR3.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The generated base stylesheet contains a rule for the flow
      container's child wrapper node with zero padding and zero margin.
- [ ] AC-2: The sections container is constructed with: horizontal
      orientation, selection disabled, non-homogeneous children, column
      spacing 12, row spacing 0, and a per-line maximum that does not
      constrain realistic section counts (asserted where construction
      parameters are testable without a GUI; otherwise verified by the
      constants' values and manual scenario M-1).
- [ ] AC-3: The set-sections operation appends section roots in input
      order and a subsequent set-sections call removes all previously
      displayed roots (no stale children), preserving current reload
      semantics.
- [ ] AC-4: Per-section update and error rendering code paths are
      unchanged (existing tests still pass unmodified).
- [ ] AC-5: `go build ./...`, `go test ./...` pass; `gofmt -l -w .`
      produces no changes.
- [ ] AC-6: tokens.yaml and tokens.html spacing descriptions state
      横 2 unit / 縦 0 for セクション間.

## Test Notes

- AC-1 translates to a unit test on the stylesheet-building function
  (string containment), next to the existing style tests.
- AC-2/AC-3 involve GTK widget construction, which the test suite cannot
  instantiate headlessly (existing convention: GUI behavior is verified
  manually). Cover what is testable without a GUI (constant values used
  for spacing); the rest is covered by VERIFICATION.md manual scenarios
  M-1/M-2.
- AC-4 is regression-covered by the existing `internal/ui` tests.
- Table-driven style per test/README.md when adding cases.

## Out of Scope

- Any config option for layout switching (the vertical layout is removed,
  not made selectable).
- Homogeneous/grid-aligned cells.
- Changes to section internals (label/output structure, markup handling).
- Reordering or sorting sections beyond config order.
