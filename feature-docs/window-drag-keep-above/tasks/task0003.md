# Task Plan: task0003 — app wiring: keep_above routing + toggle write-back

## Goal

Wire the keep-above flows through the app layer: config value to the UI at
startup/reload, and the menu toggle to immediate apply plus config
write-back off the GTK main loop.

## Requirements

FR2 (apply half), FR3 (routing half), NFR2

## Scope

### Files to Create
- None.

### Files to Modify
- `internal/app/app.go` — extend the app-side `UI` seam with `SetKeepAbove(bool)`; register the toggle callback at construction; route callback → immediate apply + write-back scheduled off the main loop (reuse the serialized reload worker's goroutine discipline or a dedicated worker)
- `internal/app/reload.go` — include keep_above in the dispatched UI projection (`SetKeepAbove(cfg.Window.KeepAbove)`) on startup and every successful reload
- `internal/app/app_test.go` — tests via fakes

## Design

- Compiles against IMPLEMENTATION.md contracts (`config.UpdateKeepAbove`,
  ui `SetKeepAbove`/`onKeepAboveToggle`). This task owns the real wiring.
- Toggle flow: callback (GTK main loop) → immediately `SetKeepAbove(new)`
  (already on main loop) → hand the write-back to a non-main-loop goroutine
  (`config.UpdateKeepAbove(path, new)`); on error, surface via the existing
  config-error banner path WITHOUT reverting the runtime state.
- The write-back triggers the watcher → serialized reload with identical
  values; must be a no-op visually (idempotent apply — existing property).
- Reload flow: successful reload applies `cfg.Window.KeepAbove` alongside
  window settings, keeping config authoritative after edits.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Startup and successful reload dispatch `SetKeepAbove` with the config value (fake UI records it; ordering within the projection verified).
- [ ] AC-2: The toggle callback applies the new state immediately and calls the write-back seam with (config path, new value), executed off the dispatched main-loop path (verified via fakes capturing call context).
- [ ] AC-3: A failing write-back shows the config-error banner and does not revert the applied runtime state.
- [ ] AC-4: A reload carrying the same keep_above value does not produce state churn (idempotent apply observable via fake call args).
- [ ] AC-5: `go test ./...` passes headlessly; `gofmt` clean.
