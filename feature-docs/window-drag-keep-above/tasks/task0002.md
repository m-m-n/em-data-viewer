# Task Plan: task0002 — ui: whole-window drag + keep-above (menu item, backend split, EWMH)

## Goal

Make left-drag work from anywhere on the window (including over rendered
text), add the「最前面に固定」check item to the context menu, and implement
keep-above application with the X11(EWMH)/Wayland(inert) backend split.

## Requirements

FR1, FR3 (menu half), FR4, NFR1, NFR2 (isolation half)

## Scope

### Files to Create
- `internal/ui/topmost.go` — backend detection (`KeepAboveSupported`) + the small interface isolating platform specifics
- `internal/ui/topmost_x11.go` — EWMH `_NET_WM_STATE_ABOVE` add/remove via the toplevel XID and a direct X connection (pure-Go X client)

### Files to Modify
- `go.mod`, `go.sum` — add github.com/jezek/xgb
- `internal/ui/window.go` — drag gesture moved/re-registered at the window level in the CAPTURE phase, button 1 only, so child widgets cannot swallow it; plain clicks not consumed
- `internal/ui/menu.go` — check item「最前面に固定」 with current-state check mark; insensitive + WM hint on Wayland; invokes the toggle callback with the new desired state
- `internal/ui/ui.go` — `SetKeepAbove(enabled bool)` / `KeepAboveSupported() bool` methods; constructor gains `onKeepAboveToggle func(bool)`; deferred EWMH apply on realize when called pre-realize

## Design

- Contracts in IMPLEMENTATION.md Shared Components are binding (method
  signatures, defer-to-realize, check-state tracking on both backends).
- Drag (FR1): a window-level drag gesture in the capture phase with a
  standard drag threshold; on threshold exceeded, start the compositor
  interactive move (same mechanism as today). Button restricted to
  primary; right-button path untouched. Click-through must remain: no
  claiming of sequences for non-drags.
- Backend split (FR4): detect via the GDK display's concrete type. X11:
  resolve the XID from the toplevel surface; send `_NET_WM_STATE` client
  messages (add/remove ABOVE) to the root window over the X connection;
  connection opened lazily and reused; failure → supported=false + log.
  Wayland: `KeepAboveSupported()` false; menu item insensitive with hint
  text; `SetKeepAbove` still records state for the check mark.
- Keep GTK-free logic (menu state/sensitivity derivation from
  (enabled, supported)) in a pure function for unit testing.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The pure state-derivation function returns (check, sensitive, hint) correctly for all (enabled, supported) combinations (unit-tested).
- [ ] AC-2: Drag gesture is registered at window level in capture phase, button 1 only (constructive assertion where testable; behavior via M-1: drag from over text moves the window; right-click still opens the menu).
- [ ] AC-3: On X11/XWayland, `SetKeepAbove(true)` results in `_NET_WM_STATE_ABOVE` on the toplevel (M-2: stays above other windows) and `SetKeepAbove(false)` removes it; pre-realize calls apply on realize.
- [ ] AC-4: On native Wayland, the item is insensitive with the WM hint, no X11 code path executes, no crash (M-3).
- [ ] AC-5: The menu check mark reflects the effective state on both backends.
- [ ] AC-6: `go build ./...` succeeds; unit tests pass headlessly; `gofmt` clean.
