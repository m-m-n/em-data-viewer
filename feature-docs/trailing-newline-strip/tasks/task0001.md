# Task Plan: task0001 — Strip trailing newlines at render time

## Goal

Section display text never ends with newline characters: the replace, append, and error display paths all strip trailing newlines at the event-translation point before the text reaches the UI.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2

## Scope

### Files to Create

- (none expected)

### Files to Modify

- `internal/app/events.go` — apply trailing-newline stripping in the event-translation function for all three event kinds
- `internal/app/app_test.go` — add/adjust tests covering the stripping behavior
- `internal/app/events_test.go` — only if the implementer chooses a dedicated test file for the translation function; otherwise untouched

## Design

- The event-translation function (the single point where replace, append, and error events become UI content) postprocesses the final display text: remove all newline characters at the end of the text, treating a carriage return immediately before a removed newline as part of the line ending.
- Precondition: text may be empty, may consist only of newlines, may contain interior blank lines, and (for replace/append) may contain validated Pango markup.
- Postcondition: returned display text has no trailing newline characters; interior content (including blank lines) is byte-for-byte unchanged; text of only newlines becomes the empty string.
- Applies uniformly: replace path (interval stdout), append path (joined buffered lines), error path (`error: {message}` — strip the message's trailing newlines before prefixing). Ring buffer contents and the runner layer are not modified.
- Ordering with markup rendering: stripping operates on raw text before markup validation/rendering for the replace/append paths, so markup handling is unaffected.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A replace event whose text ends with one newline renders with no trailing newline (FR1)
- [ ] AC-2: A replace event whose text ends with multiple newlines renders with all of them removed (FR1)
- [ ] AC-3: An append event whose buffered snapshot ends with empty lines renders with no trailing newlines, and the buffer's stored lines are unchanged (FR2)
- [ ] AC-4: An error event whose message ends with a newline displays `error: {message}` with no trailing newline (FR3)
- [ ] AC-5: Text with an interior blank line keeps that blank line; only the trailing newlines are removed (FR4)
- [ ] AC-6: Text consisting only of newlines renders as the empty string (FR5)
- [ ] AC-7: A trailing carriage-return + newline pair is fully removed; interior carriage returns are untouched (SPEC Edge case 1)
- [ ] AC-8: `go build ./...`, `go test ./...`, `gofmt -l -w .` all pass clean (NFR2)

## Test Notes

- All criteria are unit-testable against the event-translation function with table-driven cases (existing tests for it live in `internal/app/app_test.go` — follow their style).
- AC-3 needs a snapshot function returning lines with trailing empty entries; assert the returned display text AND that the snapshot source was not mutated.
- Check existing tests for assertions that depend on trailing newlines being preserved and update them to the new contract.

## Out of Scope

- Ring buffer or runner changes (stripping is display-only)
- Layout constants, CSS, divider/padding changes
- Markup validation changes (`internal/markup`)
