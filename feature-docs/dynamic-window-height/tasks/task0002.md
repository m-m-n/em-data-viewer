# Task Plan: task0002 — Make the monitor cap actually clip oversized content

## Goal

When content is taller than the monitor, the window really stops at the
monitor height with the overflow hidden (FR3), and the cap is re-applied
when the window's monitor changes.

## Requirements

FR3

## Scope

### Files to Create

None.

### Files to Modify

- `internal/ui/window.go` — clipping structure so the content's minimum
  height no longer propagates to the toplevel's minimum; monitor-change
  re-fit trigger
- `internal/ui/ui.go` — any wiring the clipping structure needs at the
  UI-facade level
- `internal/ui/sections.go` — only if the container restructuring touches
  how the sections view is hosted
- `internal/ui/window_test.go` — update/extend pure-logic sizing tests

## Design

### Background (review round 1, finding a207380001861ae4)

The window currently applies the capped height via a default-size request,
but the content root is a direct child of the window, so the content's
minimum height becomes the toplevel's minimum request. The toolkit ignores a
default size smaller than the minimum request, so content taller than the
monitor pushes the window past the monitor height instead of being clipped.

### Clipping requirement

- Host the content in a structure that does NOT propagate the content's
  minimum height to the toplevel (the window must be allocatable at the
  monitor-cap height while the content keeps its natural height inside).
- Overflow beyond the window height is simply not visible. No scrollbar is
  ever shown (SPEC: clipped, no scrollbar requirement) and scroll
  interaction must not change what is visible.
- The measured content natural height (the refit input) must still be the
  full content height — measuring the clipping host (whose minimum may be
  0) would break grow behavior.

### Monitor-change re-cap (review round 1, finding e48df1d3ea423b9b)

- Observe the realized window's monitor (surface enter/leave or display
  geometry change notifications) and schedule the existing deferred
  reflow+refit when the monitor changes, so moving the window to a shorter
  monitor re-caps its height.

### Preserved behavior

- Minimum frame height (48px) floor, width-from-settings behavior,
  drag-to-move, context menu, keep-above, banner and styling are untouched.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Manual: with content whose natural height exceeds the monitor
      height, the window's height equals the monitor height (not the
      content height) and the overflow is not visible.
- [ ] AC-2: Manual: no scrollbar appears in the clipped state, and scroll
      gestures do not reveal hidden content.
- [ ] AC-3: Manual: moving the window to a monitor with a smaller height
      re-caps the window to that monitor's height.
- [ ] AC-4: Manual: grow/shrink-to-content behavior from task0001 still
      works when content fits the monitor (window height equals content
      height, follows changes).
- [ ] AC-5: Manual: zero sections still shows the 48px-minimum draggable
      frame.
- [ ] AC-6: All existing automated tests pass unchanged in intent
      (`go build ./...`, `go test ./...`, `gofmt -l -w .` clean); pure
      sizing-logic tests are kept/extended for any new pure helper.

## Test Notes

- Keep any new pure computation (e.g. deciding the applied height from
