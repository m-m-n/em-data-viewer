# Task Plan: task0001 — GNOME Shell keep-above extension

## Goal

A self-contained GNOME Shell 50 extension that keeps every em-data-viewer
window always-on-top while enabled, and fully reverts its effect when
disabled.

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2

## Scope

### Files to Create
- `contrib/gnome-shell-extension/keep-above@em-data-viewer.m-m-n.github.io/metadata.json`
  — extension identity: uuid, name, description, shell-version `["50"]`
- `contrib/gnome-shell-extension/keep-above@em-data-viewer.m-m-n.github.io/extension.js`
  — the extension logic (ESM, default-exported extension class)

### Files to Modify
- None

## Design

See IMPLEMENTATION.md Shared Components for the UUID, source directory
path, and target app id literals.

Extension class responsibilities (lifecycle contract):

1. **enable**: (precondition: called by Shell when the extension turns on)
   - Scan all currently existing windows and run the matching flow (FR3).
   - Start watching the display for newly created windows; each new window
     enters the matching flow (FR2).
   - Postcondition: every current and future matching window is set
     always-on-top via Mutter's make-above window operation.
2. **Matching flow** for one window (FR2):
   - If the window's app id (GTK application id, falling back to the
     window class) equals the target app id → set it above (skip if
     already above).
   - If the app id is not yet available → attach a per-window watch that
     re-runs the check when the id properties change, and detach that
     watch as soon as a decision (match or non-match) is reached.
   - Non-matching windows are never modified.
3. **disable**: (precondition: called by Shell when the extension turns
   off or the session ends)
   - Disconnect the display-level watch and every per-window watch.
   - Revert the above state (unmake-above) on matching windows that are
     currently above.
   - Postcondition: no handlers remain connected; no window remains above
     because of this extension.

State kept by the class: the display-level handler id, the set of
per-window watches (window → handler ids), released on disable. Windows
destroyed while watched must not leave dangling handler references.

The user manually un-setting "Always on Top" on a window is respected: the
extension re-applies only on window creation or enable-time scan, never by
watching the above state (SPEC.md edge case).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: metadata.json declares exactly uuid
      `keep-above@em-data-viewer.m-m-n.github.io`, shell-version `["50"]`,
      and a name/description identifying the em-data-viewer keep-above
      helper.
- [ ] AC-2: extension.js is a valid ESM module default-exporting an
      extension class with enable/disable methods (GNOME 45+ form), with
      no imports outside GNOME Shell / Mutter built-in modules.
- [ ] AC-3: On enable, existing windows with the target app id are set
      above; windows created afterwards with the target app id are set
      above; other windows are untouched.
- [ ] AC-4: A window whose app id becomes available only after creation is
      still matched and set above; its per-window watch is disconnected
      after the decision.
- [ ] AC-5: On disable, all connected handlers are disconnected and
      matching windows currently above are reverted to not-above.

## Test Notes

GJS runs only inside GNOME Shell and is excluded from automated tests
(NFR2, project testing policy) — TDD does not apply to this task. Handling:

- AC-1/AC-2 are verified by static inspection of the two files (JSON
  validity can be checked with a generic JSON parse; no GJS runtime
  needed).
- AC-3/AC-4/AC-5 map to the manual scenarios in VERIFICATION.md
  (M-2, M-3, M-4, M-6 and the late-id edge case); implement so each manual
  step is directly observable via the Alt+Space window menu state.
- Do not add Go tests; do not touch any Go source.

## Out of Scope

- Makefile install/uninstall targets (task0002).
- Config linkage with the application's `window.keep_above` setting
  (decision: unconditional application).
- Support for shell versions other than 50; extensions.gnome.org
  publication; .deb packaging of the extension.
- Any preference UI (prefs.js).
