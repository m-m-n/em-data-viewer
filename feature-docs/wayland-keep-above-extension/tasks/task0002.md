# Task Plan: task0002 — Makefile install/uninstall targets

## Goal

`make install-extension` installs and enables the bundled GNOME Shell
extension for the current user; `make uninstall-extension` disables and
removes it.

## Requirements

FR5, FR6, NFR2

## Scope

### Files to Create
- None

### Files to Modify
- `Makefile` — add `install-extension` and `uninstall-extension` targets
  (plus `.PHONY` entries and any variables they need)

## Design

See IMPLEMENTATION.md Shared Components for the UUID and source directory
path literals. The source directory's contents are copied as-is (no
hardcoded file list), so task0002 does not depend on task0001's files
existing at implementation time — only on the pinned directory contract.

### install-extension (FR5)

1. Fail fast with a clear message when the `gnome-extensions` CLI is not
   on PATH (existing Makefile tool-probe style).
2. Determine whether this is a fresh install: the running Shell does not
   yet know the uuid (query the CLI's extension list) or the target
   directory did not previously exist.
3. Replace `~/.local/share/gnome-shell/extensions/{UUID}/` with a fresh
   copy of the source directory contents (idempotent re-install: previous
   contents removed or overwritten so stale files never survive).
4. Enable the extension via the CLI. On a fresh install the enable call
   may fail because the Shell has not scanned the new directory yet —
   tolerate that failure, and print re-login guidance whenever the
   fresh-install case was detected. In the fresh-install case the enable
   is still attempted (it registers the enabled state where supported).
5. Exit successfully in both the already-known and fresh-install cases.

### uninstall-extension (FR6)

1. Disable the extension via the CLI, tolerating failure (Shell absent,
   extension unknown, already disabled).
2. Remove `~/.local/share/gnome-shell/extensions/{UUID}/`; removing a
   non-existent directory is not an error.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `install-extension` copies the full contents of the source
      directory to `~/.local/share/gnome-shell/extensions/{UUID}/` and
      runs the CLI enable command; running it twice in a row succeeds
      (idempotent) and leaves no stale files from a previous copy.
- [ ] AC-2: On a fresh install (uuid unknown to the running Shell or the
      target directory absent beforehand), the target prints guidance
      that re-login is required on Wayland, and still exits 0.
- [ ] AC-3: When `gnome-extensions` is not on PATH, `install-extension`
      fails with a message naming the missing tool.
- [ ] AC-4: `uninstall-extension` disables (failure tolerated) and removes
      the installed extension directory; running it when the extension is
      not installed exits 0.
- [ ] AC-5: Both targets are declared `.PHONY`; existing targets
      (`build`, `test`, `dpkg`, `resources`, `icons`, `clean`) behave
      unchanged.

## Test Notes

Make targets drive user-session state (`$HOME`, the `gnome-extensions`
CLI) and are excluded from automated tests — TDD does not apply. Handling:

- AC-1..AC-4 map to manual scenarios in VERIFICATION.md (M-1, M-5 and the
  idempotence / not-installed edge cases). Verify by running the targets
  on the development machine and checking the resulting directory state.
- AC-5 is covered by the automated build/test commands still passing
  (`make build` untouched, `go test ./...` green).
- Do not modify Go source or the existing target recipes.

## Out of Scope

- The extension source itself (task0001).
- System-wide installation under `/usr/share/gnome-shell/extensions/` and
  .deb packaging of the extension (decided against).
- Automatic GNOME Shell restart or logout.
