# Task Plan: task0001 — GResource icon embedding end-to-end

## Goal

The binary carries the app icon as an embedded GResource bundle and
registers it on the icon theme at startup, so the icon appears in
dock/taskbar/window without installed hicolor icons; `make build` /
`make test` guarantee the bundle exists before any Go compilation.

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2

## Scope

### Files to Create
- `assets/icon.gresource.xml` — gresource manifest (git-tracked text)
  listing the six PNGs under the base path
- `internal/ui/resources.go` — embed + registration of the bundle

### Files to Modify
- `Makefile` — new `resources` target; `build` depends on it; new `test`
  target
- `.gitignore` — add `internal/ui/icon.gresource`

(The generated `internal/ui/icon.gresource` and intermediate PNGs under
`build/embed-icons/` are build artifacts, not scope files.)

## Design

### Makefile: resources target

- Checks both tools up front: missing `rsvg-convert` or
  `glib-compile-resources` stops with non-zero exit and a one-line error
  naming the missing tool.
- Renders `build/embed-icons/em-data-viewer-{S}.png` for S in
  16 32 48 64 128 256 from `assets/icon.svg` (exact width = height = S).
- Compiles `internal/ui/icon.gresource` from `assets/icon.gresource.xml`
  with the source directory pointing at the rendered PNGs.
- Idempotent: re-runs overwrite outputs.
- `build` target: `resources` runs before the Go compile step. New `test`
  target: depends on `resources`, then runs the Go test suite (the same
  invocation as the previous standard test command). `.PHONY` updated.
- `icons` and `dpkg` targets remain untouched (NFR2).

### Manifest (assets/icon.gresource.xml)

Declares the six PNGs so the bundle exposes them at
`/net/laser5/em-data-viewer/icons/{S}x{S}/apps/em-data-viewer.png` — the
hicolor-like structure the GTK icon theme expects under a resource base
path (IMPLEMENTATION.md Shared Components pins this base path). Aliases
map flat rendered filenames to the sized resource paths; PNGs are stored
uncompressed (they are already compressed).

### Runtime registration (internal/ui/resources.go)

- Embeds `icon.gresource` bytes via go:embed.
- Provides one registration function with this contract:
  - Precondition: called after GTK init, before any window creation, on
    the GTK main context.
  - Behavior: constructs a resource from the embedded bytes, registers it
    globally, obtains the default display's icon theme and adds the base
    path `/net/laser5/em-data-viewer/icons` to its resource path.
  - Postcondition on success: `em-data-viewer` resolves from the bundle.
  - Failure (malformed data, no display): log one line and return —
    never panic; theme-installed icons remain the fallback (SPEC FR3).
- Wire the call into the existing UI construction path at the point that
  satisfies the precondition (after the GTK application init/activation
  begins, before `newFrame` builds the window).
- The existing `windowIconName` constant and `SetIconName` call stay
  unchanged.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: on a tree without `internal/ui/icon.gresource`, `make build`
      succeeds and produces both the bundle and the binary.
- [ ] AC-2: on a tree without the bundle, `make test` succeeds (generation
      precedes compilation).
- [ ] AC-3: with `glib-compile-resources` masked from PATH, `make resources`
      exits non-zero and names the tool; same for `rsvg-convert`.
- [ ] AC-4: `gresource list internal/ui/icon.gresource` shows exactly the
      six entries `/net/laser5/em-data-viewer/icons/{S}x{S}/apps/em-data-viewer.png`
      for S in 16/32/48/64/128/256.
- [ ] AC-5: after a full `make build`, `git status --porcelain` shows no
      generated artifact (bundle ignored, intermediates under `build/`).
- [ ] AC-6: `make dpkg` still succeeds and its package payload structure
      (hicolor icons, .desktop, postinst/postrm) is unchanged (NFR2).
- [ ] AC-7: the registration function is called during UI construction
      before window creation, and its failure path logs without
      panicking.

## Test Notes

- Build-tooling ACs (1-6) verify via shell-level checks (make, gresource,
  dpkg-deb, git status), like app-icon's task0001.
- AC-3: mask tools via a minimal-PATH invocation; do not uninstall.
- AC-7: the GTK-dependent call site is excluded from headless unit tests
  per test/README.md; verify the wiring by code inspection and keep any
  testable pure logic (e.g. non-empty embedded bytes) in a headless test
  next to the file. TDD-awkward: acknowledged in plan; shell-level ACs
  serve as the executable contract.
- Edge: run `make resources` twice; second run must succeed (overwrite).

## Out of Scope

- Changing `icons` / `dpkg` targets or the deb payload.
- Changing the GTK application ID or `windowIconName`.
- Wayland-specific handling (X11 is the project's target; theme-resolved
  window icons cover the window/taskbar there).
- Removing the theme-install path — embedded and installed icons coexist.
