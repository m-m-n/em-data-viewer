# Task Plan: task0001 — Section divider rules (h/v) + banner gap

## Goal

Sections are separated by floating 1px divider rules — horizontal between
rows, vertical between sections sharing a row — instead of spacing alone,
and the config-error banner gains 1 unit of space above the sections.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2

## Scope

### Files to Create

None.

### Files to Modify

- `internal/ui/style.go` — divider constants + divider CSS rules + banner
  bottom spacing + gap arithmetic
- `internal/ui/style_test.go` — tests for divider CSS and constants
- `internal/ui/sections.go` — divider widget insertion during row rebuild
- `internal/ui/sections_test.go` — tests for any pure divider-count/layout
  helpers
- `internal/ui/banner.go` — only if the banner spacing cannot be expressed
  in the window stylesheet

## Design

Visual intent (design tokens are the SSOT — design-system/tokens.yaml):

- Divider color is `color.divider` (#666666) — one step darker than the
  window frame, quieter than output text. Divider thickness is
  `border.divider-width` (1px). Both are fixed constants in the ui package;
  no config style keys are added (FR3).
- Horizontal rule between adjacent rows: 1px high, spanning the row width
  minus a 1-unit (6px) inset at each end; the rows' vertical distance is
  exactly the rule (zero extra gap) (FR1).
- Vertical rule between adjacent sections in a row: 1px wide, stretching
  with the row height minus a 1-unit inset top and bottom, with 1 unit of
  breathing room on its left and right (FR2). In-row section distance is
  therefore 1 unit + 1px + 1 unit = 13px.
- Rules never touch the window frame or each other — no corners, T- or
  cross-junctions. One row → no horizontal rule; one section in a row → no
  vertical rule; zero sections → no rules at all.
- Config-error banner: 1 unit of vertical space between the banner's
  bottom edge and the sections below (FR5).

Component behavior:

- Dividers are stateless generic box widgets with dedicated CSS classes
  (`dv-hdivider` / `dv-vdivider`), created and discarded together with the
  row boxes during the row rebuild. The rebuild's postcondition extends to:
  N rows → N−1 horizontal dividers appended between row boxes; a row of M
  sections → M−1 vertical dividers between section roots. Row boxes and the
  outer vertical box use zero intrinsic spacing — all gaps come from the
  divider margins (FR4).
- The packing computation keeps its existing contract but receives the
  divider footprint (13px) as its gap so the math matches what is rendered
  (FR4). The footprint is derived from one constant set shared with the
  divider CSS emission (no duplicated arithmetic).
- The window-level stylesheet gains the two divider rules and the banner
  spacing; per-section style handling, style merging, and the SPEC config
  schema are untouched (FR3, FR6).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The window stylesheet contains a `dv-hdivider` rule with the
      divider color, 1px height, 6px horizontal margins and zero vertical
      margins.
- [ ] AC-2: The window stylesheet contains a `dv-vdivider` rule with the
      divider color, 1px width and 6px margins.
- [ ] AC-3: The gap value used by the row-packing computation equals
      13px (unit + divider width + unit), and row boxes / the rows
      container are built with zero intrinsic spacing.
- [ ] AC-4: The banner styling includes 1 unit (6px) of bottom spacing
      toward the sections.
- [ ] AC-5: After a rebuild with N rows, exactly N−1 horizontal dividers
      exist between the row boxes; a row holding M sections holds exactly
      M−1 vertical dividers; zero sections produce zero dividers.
- [ ] AC-6: All pre-existing `internal/ui` tests still pass unchanged in
      intent (only assertions that pinned the old 12px gap / spacing
      values may be updated to the new constants).

## Test Notes

- AC-1/AC-2/AC-4: unit tests over the stylesheet-building functions
  (string assertions), same pattern as the existing style tests.
- AC-3: constant-value test, same pattern as the existing gap-constants
  test.
- AC-5: GTK widget construction is excluded from automated tests per
  test/README.md; if the divider interleaving is factored as a pure
  helper (e.g. computing the child sequence for a row assignment), pin it
  with table-driven tests in sections_test.go; otherwise AC-5 is verified
  by the feature-wide manual scenario (M-1) and code review.
- Edge cases: single row, single-section row, zero sections (E-1, E-2).

## Out of Scope

- Config style keys for divider color/width (explicitly rejected — FR3).
- Any change to packing behavior beyond the gap value (row assignment
  algorithm, reflow triggers stay as-is).
- Changes outside `internal/ui`.
