# Task Plan: task0001 — Greedy row-packing sections layout

## Goal

The sections container packs sections into rows greedily by natural width
(flex-wrap style): config order left→right, wrap when the next section
does not fit, no column alignment. Layout follows window resizes and
content-driven width changes. FlowBox is removed.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2

## Design

**Pure assignment function** (FR2)
- Input: ordered natural widths, the in-row gap, the available width.
- Output: ordered groups of indices, one group per row.
- Behavior: greedy accumulation; wrap when used + gap + next > available;
  at least one item per row; available <= 0 → one item per row; empty
  input → no rows. Deterministic; no widget types involved.

**Container structure** (FR1, FR5)
- The sections view's widget is a vertical box with row-gap spacing (0).
- Each row is a horizontal box with column-gap spacing (12). Children keep
  natural widths (no expand), packed from the start edge.
- Section roots (label + output vertical box) are unchanged.

**Reflow operation** (FR3, FR4)
- Measure each root's natural horizontal size (for_size unconstrained).
- Compute the assignment from the container's currently allocated width.
- If the assignment equals the currently rendered one, do nothing.
- Otherwise rebuild rows: unparent every root from its current row,
  remove old row boxes from the container, create new row boxes per the
  assignment, append roots in order.
- Postcondition: every root is parented to exactly one row box; row
  count equals the assignment's group count.

**Triggers** (FR4)
- set-sections (after building the new section set).
- update-section (content change may change natural width).
- Window default-width property notification and map signal, each
  deferring the reflow by one main-loop iteration so the new allocation
  is visible when measuring (wiring lives in the window layer; the
  sections view exposes the reflow operation).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The assignment function packs greedily: for width 6, gap 0,
      widths 1,2,2,2,2,2 the rows are [1 2 2] and [2 2 2]; an exact-fit
      item stays in the row; one unit over wraps.
- [ ] AC-2: The assignment function counts the gap toward used width; an
      item wider than the available width gets its own row; available
      <= 0 yields one item per row; empty input yields no rows.
- [ ] AC-3: The assembled stylesheet no longer contains a flowboxchild
      rule; the FlowBox-specific per-line maximum constant is gone.
- [ ] AC-4: set-sections rebuild semantics, update-section (markup +
      error style), per-section style classes, and the empty-sections
      case are unchanged (existing tests still pass unmodified).
- [ ] AC-5: An unchanged assignment does not rebuild row widgets
      (verified where testable without a GUI; otherwise by the
      assignment-comparison logic's unit test).
- [ ] AC-6: `go build ./...`, `go test ./...` pass; `gofmt -l -w .`
      produces no changes.

## Test Notes

- AC-1/AC-2 are pure-function table tests in the new sections test file
  (table-driven per test/README.md).
- AC-3 is a string-containment test on the stylesheet builder plus
  compile-time absence of the constant.
- AC-5: the assignment-equality helper gets a direct unit test; the
  widget-rebuild skip itself is GUI-bound and covered by manual scenario
  M-1..M-2.
- Widget construction/reparenting behavior is not headlessly testable
  (existing project convention) — covered by VERIFICATION.md manual
  scenarios.

## Out of Scope

- Any config option for layout behavior.
- Changes to spacing values or design tokens.
- Changes to section internals (label/output structure, markup handling).
- Row-balancing or non-greedy packing strategies.
