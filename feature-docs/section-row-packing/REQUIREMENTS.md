# セクションの貪欲行詰めレイアウト - 要件定義書

## 1. 概要

### 1.1 背景
section-flow-layout で導入した GtkFlowBox は、homogeneous=false でも列位置ごとに最大幅で揃えるグリッドを作る(GTK 実装仕様)。一番幅広のセクションが列全体を引き伸ばし、間延びした格子になる。

### 1.2 目的
各行を自然幅で貪欲に詰め、入らなくなったら次の行へ折り返すレイアウト(flex-wrap 相当)にする。

```
width 6 の例:
w1 w2 w2
w2 w2 w2
w1 w1 w1 w2
w1 w1 w1 w2 w1
w5
```

### 1.3 スコープ
- セクション一覧コンテナを GtkFlowBox から自前の行詰め(縦 Box + 行 Box)に置き換える
- セクション内部の構造(ラベル+出力)、内容・更新機構は変更しない
- 詳細方針: tmp/section-flow-layout-rework-plan.md

## 2. 機能要件

### 2.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | 貪欲行詰め | config 順に自然幅で行へ詰め、収まらなければ次の行へ | 高 |
| F02 | 詰め計算の純関数化 | 行割当の計算をウィジェットから分離しテスト可能にする | 高 |
| F03 | 再詰めトリガー | 再構築・出力更新・リサイズ・初回表示で行割当を再計算する | 高 |
| F04 | 間隔の維持 | 行内 12px(2 unit)・行間 0 を維持する | 高 |
| F05 | FlowBox の撤去 | FlowBox と flowboxchild 用スタイルリセットを取り除く | 高 |
| F06 | 既存動作の維持 | config リロード・個別更新・セクション別スタイル・エラー表示は現状のまま | 高 |

### 2.2 機能詳細

#### F01: 貪欲行詰め
- 各セクションの幅は自然幅(内容の非折返し幅)
- 現在行の使用幅 + 間隔 + 次の自然幅が利用可能幅を超えたら改行
- 各行に最低 1 セクションは必ず置く(利用可能幅より広いセクションは単独行になり、出力は従来どおり折り返す)

#### F03: 再詰めトリガー
- セクション再構築時(config リロード)
- セクション出力の更新時(自然幅が変わるため)
- ウィンドウ幅の変化時(1 メインループ反復遅らせて反映)
- ウィンドウ初回表示時(それまでは幅不明のため 1 個/行)
- 算出した行割当が直前と同一ならウィジェット再構築をしない

## 3. 非機能要件

- 新規外部依存を追加しない
- `go build ./...`、`go test ./...`、gofmt が通ること

## 4. 制約条件

- GUI の見た目の最終確認は手動(自動 E2E なし)

## 5. 成功基準

### 5.1 受け入れ基準
- [ ] 幅に余裕がある行では複数セクションが自然幅のまま並ぶ(列揃えの間延びをしない)
- [ ] 並びは config の記述順(左→右、上→下)
- [ ] ウィンドウ幅を変えると行割当が追従する
- [ ] config リロード・セクション更新・エラー表示が従来どおり動作する
- [ ] 全ユニットテストがパスする
