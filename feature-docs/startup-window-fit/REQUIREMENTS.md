# 起動時ウィンドウフィット表示 - 要件定義書

## 1. 概要

### 1.1 背景

現状の実装では、起動直後にウィンドウが設定幅・コンテンツにフィットしない過大な高さで表示され、config 内の最小 interval のセクションの2回目実行（実運用 config では約5秒後）まで正しいサイズにならない。

調査により以下が確定している:

- 起動シーケンス中の refit（高さフィット処理）は、コンテンツコンテナの allocation 確定前に走るため全て空振りする。map シグナル契機の deferred refit も allocation 確定に間に合わない
- allocation 幅 0 の間、セクション行パッキングが「1セクション=1行」に縮退し、その縮退レイアウトの幅で高さを誤確定する
- 次に refit が有効に走るのは最小 interval セクションの2回目実行の更新イベントであり、それまで過大サイズが残る

### 1.2 目的

起動時に、全セクションの初回データが揃いレイアウトが確定した状態のウィンドウを、最初から正しいフィット済みサイズで表示する。

### 1.3 スコープ

- 起動処理（初回表示まで）の見直し: Present の遅延、初回データの完了検知、タイムアウト
- refit が allocation 確定後に有効に実行されることの保証
- 起動後の定常動作（interval 更新・live reload・スタイル適用等）は変更しない

## 2. 機能要件

### 2.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | Present 遅延 | 全セクションの初回データ受領（または1秒タイムアウト）まで Present を呼ばない | 高 |
| F02 | 初回データ完了判定 | interval/stream/エラーを含む「初回データ受領」の判定 | 高 |
| F03 | タイムアウト表示 | 1秒経過で未受領セクションはラベルのみ・テキスト空のまま表示 | 高 |
| F04 | 空・エラー時の即表示 | 待つ対象がない場合は遅延せず即表示 | 高 |
| F05 | フィット済みサイズでの表示 | 表示時点の高さは縮退レイアウトではなく実レイアウトから確定する | 高 |

### 2.2 機能詳細

#### F01: Present 遅延

- 起動時、ウィンドウの Present を「全セクションの初回データ受領」または「1秒タイムアウト」のいずれか早い方まで遅延する
- 遅延中はウィンドウを完全不可視とする（Present 自体を呼ばない）

#### F02: 初回データ完了判定

- interval セクション: 初回実行の結果イベント（成功・エラーいずれも）受領で完了扱い
- stream セクション: 最初のイベント（出力・エラーいずれも）受領で完了扱い
- エラーはエラー表示として受領済み扱いとし、表示を遅らせる要因にしない

#### F03: タイムアウト表示

- タイムアウトは起動から 1 秒固定とする（config 項目にはしない）
- タイムアウト時、未受領セクションはセクション名（ラベル）のみ表示し、出力テキストは空のままとする
- タイムアウト後に届いたデータは通常の更新フロー（UpdateSection → refit）で反映し、高さも追従する

#### F04: 空・エラー時の即表示

- config ロード失敗時（エラーバナーのみの状態）およびセクション 0 個の場合は、待つ対象がないため遅延せず即表示する

#### F05: フィット済みサイズでの表示

- 表示時点のウィンドウ高さは、設定幅に対する実際の行パッキング結果から確定する
- allocation 幅 0 時の縮退レイアウト（1セクション=1行）のまま高さを確定させない
- refit は allocation 確定後に有効に実行されることを保証する（確定検知の実装方式は実装フェーズで選定）

## 3. 非機能要件

- ポーリングや固定 FPS ループを導入しない。既存のイベント駆動アーキテクチャ（ブロック待機・アイドル時 CPU 消費ほぼゼロ）を維持する
- タイムアウトが発生しない通常ケースでは、表示後に視覚的なリサイズが起こらない

## 4. 制約条件

- GTK4 (gotk4) / GNOME Wayland 環境（X11 バックエンドでも同一動作）
- GUI レイヤーは自動テスト対象外。ロジックは GUI-free パッケージに置き `go test` 可能にする（test/README.md 準拠）

## 5. 成功基準

- [ ] 起動時、ウィンドウが最初からフィット済みサイズで表示される（過大サイズの期間が存在しない）
- [ ] 最小 interval が長い config（例: 全て 1m）でも起動から1秒程度で表示される
- [ ] 初回コマンドが遅い場合（例: sleep 10）でも1秒で表示され、該当セクションはラベルのみ・テキスト空となる
- [ ] config エラー時・セクション 0 個時は即表示される
- [ ] 既存の定常動作（interval 更新・live reload・keep-above 等）に回帰がない

## 6. テストシナリオ観点

- 正常系: 全初回データが1秒以内に揃う → フィット済みサイズで一発表示
- タイムアウト系: 遅い初回コマンドを含む → 1秒で表示、未受領セクションは空、後着データで高さ追従
- 空/エラー系: config ロード失敗・セクション0個 → 即表示
- 境界: stream セクションの初回イベント、初回実行が即エラーになるコマンド

## 7. 確認事項

### 7.1 確認済み事項

- [x] 修正方針: 案1（全初回データ + allocation 確定まで Present を遅延し、正しいサイズで一発表示する）を採用
- [x] タイムアウト: 1秒固定。config 項目にはしない
- [x] タイムアウト時の表示: セクション名のみ表示、テキストは空のまま
- [x] タイムアウト後に届いたデータ: 通常の更新フローで反映し高さも追従（表示後の高さ変化はタイムアウト発生時のみ許容）
- [x] stream セクション: 最初のイベント受領で「揃った」扱いとし interval と統一
- [x] config ロード失敗・セクション0個: 即表示
- [x] 遅延中の状態: 完全不可視（Present 自体を呼ばない）
- [x] allocation 確定の検知方式: 実装フェーズで選定する
