# Task Plan: task0001 — Icon asset, build-time rendering and deb packaging

## Goal

The repository gains the SVG icon source, and `make dpkg` produces a deb
that ships hicolor icons (4 PNG sizes + scalable SVG), a .desktop entry and
maintainer scripts — with PNGs generated at build time under `build/`
(git-ignored) and a hard failure when the renderer is missing.

## Requirements

FR1, FR2, FR3, FR4, FR6, NFR1

## Scope

### Files to Create
- `assets/icon.svg` — icon source of truth (geometry specified below)

### Files to Modify
- `Makefile` — new `icons` target; `dpkg` target grows icon / desktop /
  maintainer-script packaging steps

## Design

### Icon source (assets/icon.svg)

A single SVG, viewBox 0 0 128 128, built from plain shapes only (no text,
no filters, no gradients). Element specification, top to bottom:

| # | Element | Geometry (viewBox units) | Fill / Stroke |
|---|---------|--------------------------|---------------|
| 1 | Widget body: rounded rectangle | x 8, y 8, w 112, h 112, corner radius 20 | fill `#1e1e1e`; stroke `#888888` width 5 |
| 2 | Section label bar: rounded rectangle | x 28, y 30, w 32, h 7, radius 3.5 | fill `#9e9e9e` |
| 3 | Accent output row: rounded rectangle | x 28, y 44, w 64, h 9, radius 4.5 | fill `#40ff40` |
| 4 | Output row: rounded rectangle | x 28, y 59, w 48, h 9, radius 4.5 | fill `#e0e0e0` |
| 5 | Divider: horizontal line, round caps | from (26, 76) to (102, 76) | stroke `#666666` width 3 |
| 6 | Output row: rounded rectangle | x 28, y 86, w 56, h 9, radius 4.5 | fill `#e0e0e0` |
| 7 | Output row: rounded rectangle | x 28, y 101, w 40, h 9, radius 4.5 | fill `#e0e0e0` |

Visual intent: the app's own widget window in miniature — dark rounded
panel with framed outline, abstracted output rows, one green accent row,
and a floating divider whose ends do not touch the frame.

### Makefile: icons target

- Renders `build/icons/em-data-viewer-{SIZE}.png` for sizes 48, 64, 128,
  256 from `assets/icon.svg` using rsvg-convert at exact width = height =
  SIZE.
- When rsvg-convert is not available on PATH, the target stops with a
  non-zero exit and a one-line error naming the missing tool. No fallback
  renderer, no skip.
- Re-running overwrites existing PNGs (idempotent).
- `dpkg` depends on `icons`.

### Makefile: dpkg packaging additions

Into the package root (existing `PKG_ROOT`):

- Each rendered PNG →
  `usr/share/icons/hicolor/{SIZE}x{SIZE}/apps/em-data-viewer.png`
- `assets/icon.svg` copied verbatim →
  `usr/share/icons/hicolor/scalable/apps/em-data-viewer.svg`
- A desktop entry written to
  `usr/share/applications/em-data-viewer.desktop`, mode 644, with exactly
  these keys under `[Desktop Entry]`:

  | Key | Value |
  |-----|-------|
  | Name | eM Data Viewer |
  | Comment | Data viewer application |
  | Exec | em-data-viewer |
  | Icon | em-data-viewer |
  | Terminal | false |
  | Type | Application |
  | Categories | Utility; |
  | StartupWMClass | em-data-viewer |

- `DEBIAN/postinst` and `DEBIAN/postrm`, mode 755, each running
  best-effort (guarded by command existence, failure ignored):
  1. refresh the hicolor icon cache (`gtk-update-icon-cache` on
     `/usr/share/icons/hicolor`, force + timestamp flags)
  2. refresh the desktop database (`update-desktop-database` on
     `/usr/share/applications`)

The icon name string `em-data-viewer` is the cross-task contract pinned in
IMPLEMENTATION.md Shared Components — use it verbatim everywhere above.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `assets/icon.svg` exists, is valid SVG with viewBox 0 0 128 128,
      and contains exactly the 7 elements of the specification table
      (geometry and colors match).
- [ ] AC-2: `make icons` produces
      `build/icons/em-data-viewer-{48,64,128,256}.png`, each a PNG whose
      pixel dimensions equal its size suffix.
- [ ] AC-3: with rsvg-convert absent from PATH, `make icons` exits non-zero
      and prints an error mentioning rsvg-convert.
- [ ] AC-4: `make dpkg` succeeds and the deb content lists the four hicolor
      PNG paths, the scalable SVG path, and
      `usr/share/applications/em-data-viewer.desktop`.
- [ ] AC-5: the .desktop file inside the deb contains exactly the specified
      keys/values (including `Icon=em-data-viewer` and
      `StartupWMClass=em-data-viewer`).
- [ ] AC-6: the deb control archive contains `postinst` and `postrm`, both
      executable.
- [ ] AC-7: after `make dpkg`, `git status --porcelain` reports no new
      untracked or modified files outside `assets/` and `Makefile` (all
      generated artifacts stay under git-ignored `build/`).

## Test Notes

- This is build-tooling work: verify via shell-level checks (run make
  targets, inspect outputs with dpkg-deb, file, stat) rather than Go tests.
  `go test ./...` must keep passing but no new Go test is expected.
- AC-3: simulate absence by invoking make with a PATH that excludes
  rsvg-convert (e.g. a minimal PATH containing only coreutils/make/go
  tool dirs) — do not uninstall anything.
- Edge case: re-run `make icons` twice; second run must succeed and
  overwrite.

## Out of Scope

- Any change under `internal/` (runtime icon-name is task0002).
- Installing the icon into the local system or running the postinst
  scripts on the development machine.
- Multi-theme (non-hicolor) or symbolic icon variants.
