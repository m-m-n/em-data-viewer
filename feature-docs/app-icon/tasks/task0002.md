# Task Plan: task0002 — Runtime window icon name

## Goal

The running app declares its icon by name so that, on a system where the
deb installed the hicolor icons, the window and taskbar show the app icon.

## Requirements

FR5, NFR2

## Scope

### Files to Create
- (none)

### Files to Modify
- `internal/ui/window.go` — set the top-level window's icon name at window
  construction

## Design

- At the point where the application window is constructed (the existing
  frame-construction path in `internal/ui/window.go`), set the window's
  icon name to the string `em-data-viewer` — the cross-task contract pinned
  in IMPLEMENTATION.md Shared Components.
- Icon resolution is delegated entirely to the icon theme machinery: the
  app only declares the name. On systems without the installed icon the
  call is a harmless no-op (default/no icon), which is acceptable.
- No configuration surface: the name is a compile-time constant, not user
  config.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: window construction sets the window icon name to exactly
      `em-data-viewer`.
- [ ] AC-2: `go build ./...` and `go test ./...` pass; no package outside
      `internal/ui` changes, and no GUI-free logic package gains a gotk4
      import (NFR2).

## Test Notes

- `internal/ui` is a GTK-importing package excluded from headless unit
  testing per project convention (test/README.md): AC-1 is verified by the
  feature-wide manual verification (VERIFICATION.md) and code review, not
  by a unit test. AC-2 is covered by the existing build/test commands.
- TDD-awkward: GUI-only one-line wiring; the planned handling is exactly
  the above (build/test green + manual verification), no new test file.

## Out of Scope

- Makefile / packaging changes (task0001).
- Changing the GTK application ID (`org.dataviewer.Widget` stays).
- Loading icon files from paths at runtime (theme-name lookup only).
