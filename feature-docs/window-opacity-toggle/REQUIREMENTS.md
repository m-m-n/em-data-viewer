# ウィンドウ透過度の2パターン切り替え - 要件定義書

## 1. 概要

### 1.1 背景

最前面表示時にデフォルト透過度だと濃すぎて邪魔になることがある。
単一画面ならアクティブ/非アクティブで分けても良いが、複数画面の場合は
サブモニターで濃いまま表示しておきたいケースもあるため、ユーザー操作で
明示的に切り替えられる必要がある。

### 1.2 目的

ウィンドウ背景の透過度を2パターン設定できるようにし、キー操作でその2つを
トグルできるようにする。

### 1.3 スコープ

- 対象: ウィンドウ背景（`window.style.background`）の透過度パターン
- 対象: Ctrl+T によるトグル操作
- 対象外: エラーバナー背景・枠線・セクション個別スタイルの透過度
- 対象外: 3パターン以上、任意の透過度への連続調整
- 対象外: トグル状態の設定ファイルへの永続化
- 対象外: 右クリックコンテキストメニューへの項目追加

## 2. ユースケース

### UC01: 表示が邪魔なときに薄くする

**アクター**: ウィジェットを常用するデスクトップユーザー

**事前条件**:
- ウィンドウが表示されており、キーボードフォーカスを持っている
- 現在はパターンA（デフォルトの濃い透過度）で表示されている

**基本フロー**:
1. ユーザーが Ctrl+T を押す
2. ウィンドウ背景がパターンB（薄い透過度）に切り替わる
3. 再度 Ctrl+T を押すとパターンAに戻る

**代替フロー**:
- 設定ファイルにパターンBの値が無い場合はデフォルト値が使われる

**事後条件**:
- ウィンドウの表示位置・サイズ・セクション内容は変化しない
- 設定ファイルは書き換わらない

### UC02: 画面ごとに濃さを使い分ける

**アクター**: 複数モニターを使うユーザー

**事前条件**:
- ウィンドウがサブモニター上にある

**基本フロー**:
1. サブモニターでは濃いまま（パターンA）で表示しておく
2. メインモニターへ移動させたときに Ctrl+T で薄く（パターンB）する

**事後条件**:
- 切り替えはプロセス内の状態としてのみ保持される

## 3. 機能要件

### 3.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | 第2透過度パターンの設定 | `window.style.background_alt` を設定ファイルで指定できる | 高 |
| F02 | Ctrl+T トグル | キー操作で2パターンを切り替える | 高 |
| F03 | 起動時の初期状態 | 常にパターンA（`background`）で起動する | 高 |
| F04 | 設定リロードとの整合 | 設定リロード後もトグル状態を維持する | 中 |
| F05 | デザイントークン追加 | パターンBのデフォルト値をトークンとして定義する | 中 |

### 3.2 機能詳細

#### F01: 第2透過度パターンの設定

**説明**: 既存の `window.style.background` と同じ記法（`#RRGGBBAA` 等の CSS 色）で
`window.style.background_alt` を指定できる。省略時はデフォルト値が使われる。

**ビジネスルール**:
- 値の記法・バリデーションは `background` と完全に同一に扱う
- 既存の設定ファイル（`background_alt` 無し）はそのまま動作する

#### F02: Ctrl+T トグル

**説明**: ウィンドウがキーボードフォーカスを持っている状態で Ctrl+T を押すと、
適用中の背景がパターンAとパターンBの間で入れ替わる。

**ビジネスルール**:
- 切り替えはウィンドウを再生成せずライブに反映する
- Ctrl+T 以外のキー入力は従来どおり素通しする

#### F03: 起動時の初期状態

**説明**: プロセス起動時は必ずパターンA（`background`）で表示する。

#### F04: 設定リロードとの整合

**説明**: 設定ファイルのリロードが起きても、適用中のパターン（A/B）は維持する。
リロード後の新しい値が、適用中のパターンに即座に反映される。

#### F05: デザイントークン追加

**説明**: パターンBのデフォルト値を `design-system/tokens.yaml` に
`color.surface-alt` として定義し、実行時のデフォルト表と一致させる。

**ビジネスルール**:
- 既存のドリフトガードテスト（トークンと実行時デフォルトの一致検証）を通ること

## 4. 非機能要件

### 4.1 互換性要件

- `background_alt` を持たない既存の設定ファイルが従来どおり動作する
- 起動直後の見た目は現行から変化しない

### 4.2 保守性要件

- トグルの状態遷移ロジックは GTK に依存しない純粋な関数として単体テスト可能にする
- 設定パッケージは従来どおり GTK 系パッケージを import しない

### 4.3 ユーザビリティ要件

- トグルは即座に反映され、ウィンドウのサイズ・位置は変化しない

## 5. 制約条件

- 実装言語は Go、UI は GTK4（gotk4）
- Wayland / X11 双方で同一に動作すること（キー入力はトップレベルウィンドウのフォーカスに依存）
- 設定ファイルはユーザーが手で編集する YAML であり、キー追加は後方互換であること
