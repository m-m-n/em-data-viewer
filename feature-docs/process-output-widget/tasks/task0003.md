# Task Plan: task0003 — markup package (Pango validation + fallback)

## Goal

Deliver `internal/markup`: decide whether text is valid Pango markup and
provide an escaped plain-text fallback, so the UI never feeds GTK a string
that fails markup parsing.

## Requirements

FR6, NFR3

## Scope

### Files to Create
- `go.mod`, `go.sum` — per IMPLEMENTATION.md Bootstrap contract (if absent)
- `internal/markup/markup.go` — `Render` per the Shared Components contract; escaping helper
- `internal/markup/markup_test.go`

### Files to Modify
- None.

## Design

- `Render` follows the Shared Components contract in IMPLEMENTATION.md:
  valid markup passes through unchanged with `true`; anything else returns
  the input escaped (XML special characters) with `false`.
- Validation without GTK (NFR3): treat the input as an XML fragment (wrap in
  a synthetic root, parse with the standard XML decoder) and accept only
  well-formed fragments whose element names are within the Pango tag set
  (`span`, `b`, `i`, `u`, `s`, `tt`, `sub`, `sup`, `small`, `big`,
  `markup`). Unknown elements, unclosed tags, or malformed entities →
  fallback. Text with no tags at all but containing raw `<`, `>`, `&` that
  break parsing → fallback (escaped).
- Plain text without any markup-significant characters is valid as-is
  (passes through).
- Attribute values are not whitelisted (Pango ignores unknown attributes);
  only well-formedness and the element whitelist are enforced.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Plain text without special characters passes through unchanged, reported valid.
- [ ] AC-2: Text using only whitelisted Pango tags (nested allowed, attributes allowed) passes through unchanged, reported valid.
- [ ] AC-3: Malformed input (unclosed tag, bad entity, raw `<`/`&` that breaks parsing) returns the fully escaped input, reported invalid.
- [ ] AC-4: Input with well-formed but non-whitelisted elements returns the escaped input, reported invalid.
- [ ] AC-5: Escaped output never contains unescaped `<`, `>`, `&` outside entities.
- [ ] AC-6: The package does not import gotk4; `go test ./...` passes headlessly.

## Test Notes

- Pure function — table-driven tests cover all criteria.
- Edge cases worth rows: empty string, multi-line input, `&amp;` already
  escaped, deeply nested spans, attribute containing `<` inside quotes.

## Out of Scope

- Rendering (task0004); ANSI escape interpretation (not in SPEC).
