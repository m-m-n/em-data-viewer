# Task Plan: task0008 — reload pipeline & presentation state (app layer)

## Goal

Give the app layer an authoritative per-section presentation state so
reloads restore the full display (interval output and error states
included), move blocking reload work off the GTK main loop, and make event
coalescing lose neither errors nor CPU to discarded renders.

## Requirements

FR3, FR9, NFR2

## Scope

### Files to Create
- None.

### Files to Modify
- `internal/app/app.go` — reload dispatch split: watcher goroutine does load + runner reconcile off the main loop; only UI mutations are dispatched onto it
- `internal/app/events.go` — coalesce raw events (render at dispatch time); error events are never silently swallowed; update the app-owned presentation store
- `internal/app/reload.go` — rehydrate ALL sections (interval output and error state included) from the presentation store after SetSections
- `internal/app/app_test.go` — tests for the store, error-preserving coalescing, dispatch-time rendering, and off-main-loop reload split
- `internal/config/holder.go` — holder becomes the single source for current config + error consumed by the reload path (or is removed if the store subsumes it — pick one, no write-only state)
- `internal/config/holder_test.go` — updated accordingly

## Design

Review findings addressed (reviews/round1.yaml): 2b042f9d5245580f (high),
c26a9d93221dd23c, c405caff81498dea, 8789fc90bdd0f1d1, 37eb2a866b8f7239.

- **Presentation store**: app owns `latest rendered state per section key`
  (text + isError). Every UI update (replace/append/error) writes it; the
  reload path reads it to rehydrate rebuilt widgets — interval sections and
  terminal error states are restored exactly, unlike the runner-snapshot
  approach it replaces.
- **Render at dispatch time**: pending coalesce entries hold the raw event
  (or section key + kind); the expensive snapshot/join/markup validation
  runs once per dispatched callback, not per received event.
- **Error preservation**: an error event must be rendered at least once —
  a pending, not-yet-displayed error is not silently replaced by a newer
  success (dispatch it first or queue the transition), while steady-state
  output coalescing stays bounded (at most one pending callback per
  section plus at most one preserved error transition).
- **Off-main-loop reload**: the watcher goroutine performs file load,
  holder update, and runner reconcile; only the resulting UI projection
  (window settings, section view models, banner state, rehydration data)
  is dispatched to the GTK loop. Stale-reload protection via a generation
  counter (later loads win).
- **Holder**: either the single authoritative source the reload path reads
  from (preferred), or deleted — no write-only duplicate remains.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: After a style-only reload, an interval section's last output and a failed section's error display are restored immediately (verified with fakes: store → rehydrate path).
- [ ] AC-2: An error event is always rendered at least once, even when a success event for the same section arrives before the error's callback runs.
- [ ] AC-3: Markup rendering/snapshotting for coalesced stream events happens at dispatch time — dropped intermediate events do not incur a render (observable via a counting fake around the render seam).
- [ ] AC-4: File load and runner reconcile execute off the dispatched main-loop path; only UI mutations go through dispatch (verified via fakes asserting call context/ordering).
- [ ] AC-5: A stale reload (older generation completing after a newer one) does not overwrite the newer state.
- [ ] AC-6: No write-only state remains: holder is either read by the production reload path or removed.
- [ ] AC-7: `go test ./...` passes headlessly; `gofmt` clean.

## Test Notes
