# Task Plan: task0001 — config package (schema, load, validate, watch)

## Goal

Deliver `internal/config`: YAML schema types, loading with defaults and
validation, a last-good-config holder, and a debounced file watcher that
survives editor rename/replace saves.

## Requirements

FR2, FR3 (watch side), FR9 (config-error side), NFR3

## Scope

### Files to Create
- `go.mod`, `go.sum` — per IMPLEMENTATION.md Bootstrap contract (if absent)
- `internal/config/config.go` — types (`Config`, `SectionConfig`), defaults, `Key()`
- `internal/config/load.go` — path resolution (XDG default), load, validate
- `internal/config/load_test.go`
- `internal/config/holder.go` — last-good holder: accepts a load result, keeps the previous good config on error, exposes current config + current error
- `internal/config/holder_test.go`
- `internal/config/watcher.go` — fsnotify-based watcher with debounce and rename/replace handling
- `internal/config/watcher_test.go`

### Files to Modify
- None.

## Design

- Types and `Load` follow the Shared Components contracts in
  IMPLEMENTATION.md exactly (other tasks compile against them).
- Path resolution: explicit path argument wins; otherwise
  `$XDG_CONFIG_HOME/data-viewer/config.yaml`; otherwise
  `~/.config/data-viewer/config.yaml`. Resolution is a pure function
  (inputs: explicit path, environment values, home dir) so it is testable.
- Validation errors (treated the same as parse errors): missing command,
  unknown mode, missing/unparsable interval for interval mode, non-positive
  max_lines. Defaults applied after validation: window 400x600, max_lines
  100.
- Watcher: watches the config file's DIRECTORY (not the file inode) so
  rename/replace saves keep working; filters events to the target file name;
  debounces bursts into one notification.
- Holder: three observable outcomes — (initial load ok), (reload ok →
  replaces current), (reload failed → previous config retained AND error
  retained until next success).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A valid YAML config loads into `Config` with defaults applied (window size 400x600 when omitted, max_lines 100 when omitted).
- [ ] AC-2: Each validation failure listed in Design yields a descriptive error and no config.
- [ ] AC-3: Path resolution honors explicit path > `$XDG_CONFIG_HOME` > `~/.config` in that order.
- [ ] AC-4: `SectionConfig.Key()` is stable under style-only changes and differs when command, mode, interval, or max_lines change.
- [ ] AC-5: The holder retains the last good config and surfaces the error after a failed reload; a subsequent successful reload replaces both.
- [ ] AC-6: The watcher notifies within its debounce window for both in-place writes and rename/replace saves of the target file (verified with a temp dir).
- [ ] AC-7: The package does not import gotk4; `go test ./...` passes headlessly.

## Test Notes

- All criteria are unit-testable (`t.TempDir()` for watcher/holder tests).
- Watcher tests use generous timeouts to stay CI-safe; debounce verified by
  counting notifications after a burst of writes.
- Edge cases: zero sections (valid), config file deleted (watcher keeps
  watching the directory; deletion is not a notification requirement).

## Out of Scope

- Wiring the watcher/holder into the app loop (task0005).
- Any GTK/UI concern; process execution.
