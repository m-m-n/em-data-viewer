# Task Plan: task0006 — style contract alignment (SPEC keys → internal styling)

## Goal

Make the documented SPEC config style keys actually work: window
`border_color` / `border_width` and section `font` / `color` apply over the
defaults, while keeping the existing internal keys functional.

## Requirements

FR3 (style reflection), NFR3

## Scope

### Files to Create
- None.

### Files to Modify
- `internal/ui/style.go` — accept SPEC schema keys via alias translation to the internal keys; keep the token-default table as the single defaults source
- `internal/ui/style_test.go` — tests for the alias translation and a drift guard against `design-system/tokens.yaml`

## Design

Review findings addressed (reviews/round1.yaml): 6d014cd3b45e2335 (high),
e55a59ae37149c6b, 39d4e01f33f7307c, c4b46fb04993ee7e.

- The SPEC Config Schema keys are the PUBLIC contract: window styles
  `background`, `border_color`, `border_width`; section styles `font`,
  `color`. They must take effect. Internal role keys (`frame`,
  `frame-width`, `output-*`, `label-*`) stay as the richer superset.
- Translation layer (pure function, GTK-free): before merging, map SPEC
  keys onto internal keys — `border_color`→frame color, `border_width`→
  frame width (bare numbers treated as px), section `color`→output text
  color, section `font`→output font (a Pango font description like
  "monospace 12"; split into family/size for the internal keys or apply
  as-is if the internal representation supports a combined value). When
  both a SPEC key and its internal equivalent are present, the SPEC key
  wins (documented behavior beats internal alias).
- Unknown keys remain ignored (existing behavior).
- Drift guard: a test parses `design-system/tokens.yaml` (path relative to
  the repository root; yaml.v3 is already a dependency) and asserts the
  ui defaults table matches the token values, so token/runtime drift fails
  the test suite.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A section style `{font: "monospace 12", color: "#ffffff"}` (SPEC schema example) changes the rendered output font and color from the defaults (verified via the merge/translation logic, GTK-free).
- [ ] AC-2: A window style `{border_color: "#ff0000", border_width: 2}` changes the frame color and width values produced by the style logic.
- [ ] AC-3: Numeric-only `border_width` values are interpreted as pixels.
- [ ] AC-4: Existing internal keys keep working; when a SPEC key and its internal equivalent conflict, the SPEC key wins.
- [ ] AC-5: A test asserts the defaults table matches `design-system/tokens.yaml` values (drift guard).
- [ ] AC-6: `go test ./...` passes headlessly; `gofmt` clean.

## Test Notes

- All criteria unit-testable on the pure merge/translation functions.
- Edge rows: empty style map, SPEC key with empty value, unparsable font string (fall back to defaults without error).

## Out of Scope

- SPEC.md changes (the schema stays as documented — implementation aligns to it).
- Any GTK widget code changes beyond consuming the translated values.
