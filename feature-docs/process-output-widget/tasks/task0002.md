# Task Plan: task0002 — runner package (process lifecycle, interval/stream, reconcile)

## Goal

Deliver `internal/runner`: executes section commands in interval or stream
mode, emits output/error events on a channel, reconciles the running set
against a new section list, and shuts everything down cleanly.

## Requirements

FR3 (reconcile side), FR4, FR5, FR9 (command-error side), NFR2, NFR3

## Design

- `Event` / `Runner` follow the Shared Components contracts in
  IMPLEMENTATION.md exactly.
- Commands run through the user's shell (`sh -c` semantics) with stdout
  captured; stderr is not displayed (diagnostics may go to the app log).
- Interval worker: run → emit one `replace` event with full stdout → sleep
  the configured interval → repeat. A failing run (spawn failure or non-zero
  exit) emits an `error` event instead of `replace` and the cycle continues.
- Stream worker: spawn once, emit `append` per stdout line; the ring-buffer
  trimming to max_lines is applied by the CONSUMER side contract? — NO:
  trimming is runner-side state; the worker maintains the buffer and each
  `append` event carries only the new line. Process exit (any reason) emits
  `error`; no automatic restart (SPEC FR5).
- Ring buffer is a separate, purely in-memory type: append one line, drop
  oldest beyond capacity, snapshot contents in order. Stream worker uses it
  so a reconnect of the UI (style reload) can re-render current content —
  exposed via a `Snapshot(key)` accessor on the Runner.
- Reconcile (`Apply`): diff by `SectionConfig.Key()` — start added, stop
  removed, restart changed, leave identical keys running. Stopping uses
  graceful termination first, forced kill after a short timeout.
- Concurrency: each section runs in its own goroutine; events funnel into
  the single channel; `Stop` waits for workers to finish and then closes the
  channel. Bounded internal buffering so a stalled consumer cannot grow
  memory unboundedly.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Interval mode emits a `replace` event with the command's full stdout for each run, at approximately the configured interval.
- [ ] AC-2: Stream mode emits an `append` event per stdout line as it arrives.
- [ ] AC-3: The ring buffer never exceeds max_lines, drops oldest first, and `Snapshot` returns current lines in order.
- [ ] AC-4: A failing command (spawn failure or non-zero exit in interval mode; process exit in stream mode) emits an `error` event for that section's key only, and other sections keep running.
- [ ] AC-5: `Apply` starts added keys, stops removed keys, restarts changed keys, and leaves unchanged keys running (observable via event flow and process behavior).
- [ ] AC-6: `Stop` terminates all child processes (a stubborn child is killed after the timeout) and closes the event channel.
- [ ] AC-7: The package does not import gotk4; `go test ./...` passes headlessly.

## Test Notes

- Use tiny shell commands (`echo`, `printf`, short-lived loops, `sleep`) as
  test fixtures; keep intervals short for fast tests.
- AC-5's "unchanged keeps running" observable via a stream section that
  keeps emitting across an `Apply` with the same key.
- AC-6 stubborn-child case uses a command that ignores the graceful signal.
- Timing assertions use generous tolerances (CI-safe).

## Out of Scope

- Consuming events / UI updates (task0005); markup handling (task0003).
- Automatic restart of exited stream processes (SPEC: explicit non-goal).
