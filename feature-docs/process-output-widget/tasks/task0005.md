# Task Plan: task0005 — app wiring + entry point (config → runner → UI)

## Goal

Deliver `internal/app` and `cmd/data-viewer`: CLI argument handling, startup,
the live-reload loop (config watcher → holder → runner reconcile → UI), event
routing onto the GTK main loop, and clean shutdown from the quit menu.

## Requirements

FR2 (CLI side), FR3 (wiring), FR8 (quit side), FR9 (routing), NFR2

## Scope

### Files to Create
- `go.mod`, `go.sum` — per IMPLEMENTATION.md Bootstrap contract (if absent)
- `cmd/data-viewer/main.go` — flag/argument parsing (optional config path), app start
- `internal/app/app.go` — construction and lifecycle: initial load, UI setup, goroutines, shutdown ordering
- `internal/app/reload.go` — watcher notification → reload via holder → apply outcome (styles to UI, section list to runner, banner set/clear)
- `internal/app/events.go` — runner event consumption: markup validation, per-kind translation (`replace`/`append` with buffer snapshot/`error`), dispatch to UI on the main loop
- `internal/app/app_test.go` — tests for the GTK-free decision logic (see Test Notes)

### Files to Modify
- None.

## Design

- Compiles exclusively against the Shared Components contracts in
  IMPLEMENTATION.md (`config.Load`/`Watcher`/holder, `runner.Runner`/`Event`,
  `markup.Render`, `ui.UI`). This task OWNS the real wiring — no placeholder
  may remain anywhere (integration owner per plan rules).
- Startup: resolve config path (explicit argument wins) → initial load via
  holder (failure → empty config + banner per FR9) → build UI → apply window
  settings and section view models → start runner with the section list →
  start watcher goroutine and event-consumer goroutine → run the UI loop.
- Reload flow (FR3): watcher notification → reload through the holder →
  on success: clear banner, apply window/style settings to UI, set section
  view models, `Apply` the new section list to the runner; on failure: set
  banner only, everything else untouched (last-good behavior).
- Event flow: each runner event is translated GTK-free — `replace` text and
  stream lines go through markup validation; `append` renders the section's
  current buffer snapshot joined as lines; `error` maps to the UI error
  flag — then dispatched to the UI on the GTK main loop (NFR2: no direct
  cross-goroutine GTK access; keep per-event work constant-time).
- Shutdown (FR8): quit callback → stop watcher → stop runner (children
  terminated per its contract) → exit the UI loop. Shutdown is idempotent.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: With no argument the XDG config path is used; an explicit path argument overrides it (decision logic unit-tested).
- [ ] AC-2: Startup with an unloadable config shows the banner and an empty window instead of crashing (translation logic unit-tested; manual M-2).
- [ ] AC-3: A successful reload applies styles and section changes (runner `Apply` called with the new list, banner cleared); a failed reload sets the banner and changes nothing else (decision logic unit-tested; manual M-2).
- [ ] AC-4: Runner events map correctly: `replace`→validated markup content, `append`→buffer snapshot content, `error`→error-flagged message, each targeting only its section key (unit-tested against fake UI/runner seams).
- [ ] AC-5: Quit stops the watcher and the runner before the process exits (manual M-3; shutdown ordering unit-tested via fakes where feasible).
- [ ] AC-6: `go build ./...` succeeds and `go test ./...` passes headlessly.
