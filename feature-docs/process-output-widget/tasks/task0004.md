# Task Plan: task0004 — ui package (GTK window, frame, sections, drag, menu, banner)

## Goal

Deliver `internal/ui`: the frame-only GTK4 window with stacked sections,
drag-to-move, right-click context menu, config-error banner, and live style
application — exposing the `ui.UI` contract for the app layer.

## Requirements

FR1, FR6 (rendering side), FR7, FR8 (menu side), FR9 (display side), NFR1

## Design

- `ui.UI` follows the Shared Components contract in IMPLEMENTATION.md; all
  methods assume main-loop context (the app layer guarantees it).
- Window (FR1): client-side decorations disabled; the app draws only a frame.
  Dragging anywhere on the window background starts a compositor-side
  interactive move (Wayland-compatible; no absolute positioning anywhere).
- Visual defaults (from `design-system/tokens.yaml`, single defaults table
  in `style.go`; user config style values override per key):
  - window: semi-transparent dark background `#1e1e1eee`, 1px `#888888`
    frame, 8px rounded corners, inner padding 12px (2 × 6px spacing unit)
  - sections: stacked vertically, 12px gaps, no divider lines; optional dim
    (`#9e9e9e`) sans-serif 9pt name label above the output, 6px apart;
    output text monospace 12pt `#e0e0e0`, preserves whitespace, wraps long
    lines
  - config-error banner (FR9): full-width bar pinned above all sections,
    background `#3a2222ee`, text `#e57373` monospace, single line
  - section command error: rendered as that section's content in `#e57373`,
    format `error: {message}`
  - empty state (zero sections): frame-only window with a minimum height so
    it stays grabbable
- Section content arrives as Pango markup already validated upstream;
  `UpdateSection` with `isError` true renders the error style instead.
- Context menu (FR8): stock GTK popover menu on right-click with a single
  終了 item invoking the quit callback. No custom menu styling.
- Style application is live: `ApplyWindow` / `SetSections` re-apply styles
  to existing widgets without recreating the window.
