# Task Plan: task0001 — Output-size default 12pt → 11pt + token sync

## Goal

Sections with no font override render their output text at 11pt by default,
and the design token file states the same value as the code default.

## Requirements

FR1, FR2, NFR1

## Scope

### Files to Create

- (none)

### Files to Modify

- `internal/ui/style.go` — change the section style default for the output
  text size from 12pt to 11pt
- `internal/ui/style_test.go` — assert the generated default section CSS uses
  11pt for output text, 9pt for labels, and that a user font override still
  wins over the default
- `design-system/tokens.yaml` — update the output font token (the monospace
  entry) size from 12pt to 11pt

## Design

- The section style defaults table in the UI layer is the single source of
  the default output text size; only its value changes.
- The design token file mirrors the same value so the token SSOT stays
  truthful (NFR-level consistency; no code reads the token file at runtime).
- Override precedence (user config `style.font` / `output-size` over
  defaults) is existing behavior and must remain untouched.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: With no overrides, the generated section CSS contains an
      output-text font size of 11pt.
- [ ] AC-2: With no overrides, the generated section CSS contains a label
      font size of 9pt (unchanged).
- [ ] AC-3: With a user font override specifying size 12, the generated
      section CSS contains an output-text font size of 12pt (override wins).
- [ ] AC-4: The output font token entry in `design-system/tokens.yaml`
      states size 11pt.

## Test Notes

- AC-1〜AC-3 map to unit tests on the section CSS generation (table-driven,
  per test/README.md conventions; the style package is GUI-free and testable
  headlessly).
- AC-4 is a file-content check; verified by inspection during verify phase
  (no runtime code reads the token file — a unit test is not required).

## Out of Scope

- Label size, window style, color, or any other default
- Config schema or override precedence changes
- Historical feature-docs of past features (their recorded 12pt stays as-is)
