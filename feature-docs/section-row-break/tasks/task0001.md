# Task Plan: task0001 — Forced row-break config entry

## Goal

A `- type: break` entry in the sections config forces the row packing to
end the current row at that position; everything else about section
rendering, processes, and validation behaves exactly as before.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify

- `internal/config/config.go` — break representation on the section model
  (a type discriminator; break entries are recognizable at every layer).
- `internal/config/load.go` — parse the new `type` YAML field; `break`
  entries skip section validation and ignore other fields; unknown
  non-empty values are a validation error; breaks are excluded from the
  duplicate-key check.
- `internal/config/load_test.go` — TS-1..TS-4 cases.
- `internal/app/reload.go` — exclude breaks from the runner section list
  and from rehydration; convey break markers to the ui view models.
- `internal/app/app_test.go` — TS-5 cases.
- `internal/ui/sections.go` — view model break flag; section building
  skips widget creation for breaks but records forced-break positions;
  row assignment packs each break-delimited segment with the existing
  greedy width packing and concatenates the results.
- `internal/ui/sections_test.go` — TS-6..TS-8 cases.
- `internal/ui/ui.go` — only if the view-model pass-through needs a
  touch; expected unchanged.

## Design

### Config layer (FR1, FR2)

- The raw YAML section gains an optional `type` field.
  - Omitted / empty → normal section; existing validation unchanged.
  - `break` → break entry: all other fields ignored; the command / mode /
    interval / max_lines validations are skipped.
  - Any other value → validation error naming the value, flowing through
    the existing config-error / last-good path.
- Duplicate-key validation considers only non-break entries; any number
  of breaks is valid.
- Precondition for downstream layers: a loaded config's sections slice
  preserves config order and marks break entries distinguishably.

### App layer (FR2, FR3)

- Runner conversion and rehydration iterate only non-break entries — a
  break never starts a process and never restores content.
- View-model conversion emits one entry per config entry (order
  preserved) with a break marker the ui layer can branch on.

### UI layer (FR4, FR5)

- Section building creates no widgets, no style entry, and no order key
  for break entries; instead it records the forced-break positions
  relative to the real sections.
- Row assignment: split the real sections into segments at the forced
  breaks; pack each segment with the existing width-based greedy
  algorithm; concatenate the per-segment rows in order. Empty segments
  (leading / trailing / consecutive breaks, breaks-only config) yield no
  rows.
- Row building, divider interleaving, and the assignment-equality
  rebuild skip are untouched: a break-created boundary is
  indistinguishable from a natural wrap in the rendered tree.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A config containing `- type: break` between two sections
      loads successfully, and the entry after the break always starts a
      new row even when the current row has remaining width.
- [ ] AC-2: `type` omitted keeps existing behavior; `type: break` with
      other fields present still loads as a break; `type` with any other
      non-empty value fails validation with an error naming the value.
- [ ] AC-3: Two or more break entries in one config do not trigger the
      duplicate-key error.
- [ ] AC-4: The runner section list and the rehydration list contain no
      break entries.
- [ ] AC-5: Within each break-delimited segment, width-based wrapping
      behaves exactly as before (same assignments as the current
      algorithm given the same widths).
- [ ] AC-6: Leading, trailing, and consecutive breaks — and a config of
      breaks only — produce no empty rows and no extra dividers.
- [ ] AC-7: Divider counts for an assignment produced with breaks equal
      those of the same assignment produced by natural wrapping.

## Test Notes

- All new logic is pure/GUI-free: config parsing (load_test), app
  conversions (app_test), and segment packing (sections_test) are
  table-driven unit tests per test/README.md.
- Widget construction paths (setSections widget creation, rebuildRows)
  remain excluded from automated tests as before; the pure
  assignment-level tests (TS-6..TS-8) cover the layout decisions.
- Edge cases worth covering: break at index 0, break at the end,
  consecutive breaks, breaks-only, zero entries.

## Out of Scope

- No changes to divider rendering, spacing constants, or design tokens.
- No update to config.yaml.example (not required by SPEC.md).
- No writeback changes (`UpdateKeepAbove` is node-level and preserves
  unknown entries already).
